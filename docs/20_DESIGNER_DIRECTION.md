# 20 DESIGNER DIRECTION

這份文件是給設計者使用的方向控制文件。

它不是工程 checklist，也不是特定產品範本。它的用途是讓非工程背景的設計者能持續帶領 agent：修正誤讀、保護產品意圖、標出不做什麼，並要求 agent 回到真源文件，而不是被實作細節帶走。

## 設計者要控制什麼

Agent 可以幫忙整理、追問、實作、驗證，但產品方向必須由設計者控制：

- 這個產品真正要解決什麼
- 這個產品不是什麼
- 哪些能力是目前主線
- 哪些能力只是未來可能
- 哪些體驗不能被一般模板帶偏
- 哪些使用者誤解絕對不能發生
- 哪些決策是刻意取捨，不是 agent 可以自行推翻

## 何時要介入

看到以下情況時，設計者應該停止 agent 繼續實作，先修方向：

- Agent 把產品套進一般 SaaS / marketplace / dashboard 模板
- Agent 開始補你沒有說過的商業模式、角色或流程
- Agent 把未來功能包裝成現在要做
- Agent 用工程方便性改變產品規則
- Agent 忽略「不做什麼」或已知不確定性
- Agent 回報完成，但只是在完成畫面或技術任務
- Agent 的文案讓產品看起來比實際階段成熟
- Agent 想把沒有決策的問題直接實作掉

## 可以直接對 agent 說的話

```text
你現在偏離產品方向了。請先不要改 code，回到 PRODUCT_TRUTH 和 RULES，重新整理這個產品是什麼、不是什麼，以及目前主線是什麼。
```

```text
這不是我要的產品判斷。請把你的假設列出來，標出哪些沒有真源支持，然後改成需要我回答的 PM 問題。
```

```text
請不要把這個功能套成一般產品模板。先列出本產品和一般模板不同的地方，再重新提出實作範圍。
```

```text
這一版故意不做哪些事？請寫進 NON_GOALS，避免後續 agent 自己補進來。
```

```text
請用產品語言記錄這個決策：為什麼這樣做、排除什麼替代方案、取捨是什麼、什麼情況要重估。
```

## Direction Check

每次進入實作前，設計者可以要求 agent 回答：

| 問題 | 目的 |
|---|---|
| 這次要完成哪一條能力？ | 避免 agent 一次做太多 |
| 這條能力對應哪份真源？ | 避免靠聊天記憶實作 |
| 這次故意不做什麼？ | 防止 scope creep |
| 哪些假設還沒有被設計者確認？ | 防止 agent 自行補規則 |
| 這個做法會不會讓產品看起來像另一種模板？ | 保護定位 |
| 完成後怎麼驗證不是只有畫面？ | 保持完成判準 |

## 設計者回答後要寫回哪裡

- 產品方向：`02_PRODUCT_TRUTH.md`
- 名詞與語意：`03_GLOSSARY.md`
- 硬規則 / 禁止事項：`04_RULES.md`
- 未決問題：`05_PM_QUESTIONS.md`
- 流程與狀態：`06_FLOWS_AND_STATES.md`
- 能力主線與關閉能力：`07_CAPABILITY_MAP.md`
- 重要取捨：`17_DECISION_LOG.md`
- 產品矛盾：`18_CONTRADICTION_AUDIT.md`

## 核心原則

Designer-led 不代表設計者要懂所有工程細節。

Designer-led 代表 agent 不能用工程細節、通用模板或自己的猜測取代產品判斷。當方向不清楚時，agent 應該回到設計者、回到真源文件、回到明確取捨。
