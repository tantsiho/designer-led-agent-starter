# 00 START HERE

這是代理進場入口。

本模板的工作順序是：

1. 讀原始設計稿
2. 抽產品真相、規則、角色、流程、狀態
3. 提出 PM 問題
4. 設計者回答後，更新真源文件
5. 建立能力地圖
6. 做架構、資料真源、環境、防禦判斷
7. 才開始實作
8. 實作後稽核與回寫

這個順序不是只跑一次。每次新功能、新風險、新環境差異、新產品判斷出現時，都要回到文件，更新真源，再繼續往下做。

## 代理不得跳過的事

- 不得直接從 `01_RAW_DESIGN.md` 寫 code
- 不得把一般產品模板套到本專案
- 不得把 UI 當作完成
- 不得把本地 smoke 當作上線保證
- 不得因為使用者是新手，就降低完成判準

## 第一輪要做什麼

如果 `02_PRODUCT_TRUTH.md` 到 `12_ACCEPTANCE_AND_VERIFICATION.md` 還是空的，第一輪只做整理，不做實作。

請產出或更新：

- `02_PRODUCT_TRUTH.md`
- `03_GLOSSARY.md`
- `04_RULES.md`
- `05_PM_QUESTIONS.md`
- `06_FLOWS_AND_STATES.md`
- `07_CAPABILITY_MAP.md`

若設計稿太大，分批整理，但要留下「已整理範圍」與「尚未整理範圍」。

## 開發中要做什麼

每次實作後，代理必須判斷是否需要更新：

- 產品真相
- 名詞
- 規則
- PM 問題
- 流程 / 狀態
- 能力地圖
- 架構決策
- 資料真源
- 環境模型
- 風險防禦
- 驗收驗證
- build audit

如果有新發現但沒有回寫文件，後續代理會重新踩同一個坑。
