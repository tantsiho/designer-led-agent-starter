# 15 NATURAL LANGUAGE EXAMPLES

這份文件給不想記指令的新手使用。你可以直接用自然語言跟代理說話。

## 貼上原始設計稿時

```text
這是我的產品設計稿。先不要寫 code，請先幫我整理產品真相、角色、規則、流程、矛盾和需要我回答的問題。
```

```text
這份設計很亂，你先不要急著實作。請先分出哪些是核心規則、哪些只是想法、哪些可能是未來功能。
```

## 要代理追問你時

```text
請你扮演 PM，找出這份設計裡不清楚、互相矛盾、或做下去會卡住的地方，然後用我能回答的方式問我。
```

```text
請不要用工程術語問我。把問題改成產品判斷題，讓我回答這個功能應該怎麼運作。
```

## 回答完問題後

```text
這些是我的回答。請更新產品真相、規則、流程和能力地圖，不要直接開始寫 code。
```

```text
請把剛剛釐清的規則寫回文件，並標出還有哪些問題沒有回答。
```

## 準備開始實作時

```text
現在先做第一條核心流程。開始前請先讀真源文件，列出這條能力需要的 UI、API、資料保存、權限、錯誤狀態和驗證方式。
```

```text
先不要一次做全部。請選出最小但完整的一條能力閉環，做完後要能驗證不是只有畫面。
```

## 擔心 AI 做半套時

```text
請檢查這個功能是不是只是 UI。API、資料保存、權限、錯誤狀態、重新整理後資料是否存在，都要逐項確認。
```

```text
請用 BUILD_AUDIT 的格式反查：哪些真的完成，哪些只是看起來有，哪些還沒驗證。
```

## 擔心本地可以、上線不行時

```text
請區分這次驗證是 local、engineering mode、staging 還是 production-like。不要把本地通過說成上線可用。
```

```text
這個功能如果要上線，還缺哪些 env、外部服務、資料庫、權限或 post-deploy smoke？
```

## 擔心安全和濫用時

```text
請用防禦思維檢查這條流程：越權、重複提交、direct route、資料外洩、錯誤訊息、audit、rate limit 有沒有問題。
```

```text
假設使用者想鑽漏洞，他可以怎麼濫用這個功能？請列出風險和最低防線。
```

## 發現產品方向被代理帶偏時

```text
你剛剛的理解偏向一般產品模板了。請回到 PRODUCT_TRUTH，重新整理這個產品不是什麼，然後修正規則。
```

```text
這個功能不是我要的方向。請不要直接改 code，先把產品真相和規則修正，再重新提出實作計畫。
```

## 每次做完後

```text
請回報：對應哪個真源、改了什麼、驗證了什麼、沒驗證什麼、有沒有用 mock 或 engineering mode、還需要什麼上線檢查。
```
