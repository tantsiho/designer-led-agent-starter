## 假完成反查

每次做完問：

- 是否只是 UI？
- 是否有假按鈕、假入口、假選項？
- 是否有重複入口造成產品混亂？
- API 是否真支援？
- 權限是否以正確身份判斷？
- 資料是否持久化？
- refresh / restart 後是否一致？
- 測試是否被改成接受半套？
- 是否使用 mock / engineering mode？
- 是否需要 production-like 或 post-deploy smoke？
- 是否有新的風險或規則缺口要回寫？

## Blocker 重估

高價值 blocker 解掉後，代理要判斷剩餘工作屬於：

- 仍是核心 blocker
- 必須補的完整性缺口
- 低風險 polish
- 文件 / 文案整理
- 未來工程

不得因為低風險就假裝已完成；也不得在非 blocker 上無限停留。
